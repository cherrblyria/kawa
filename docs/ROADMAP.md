# Kawa Roadmap

This roadmap is intentionally lightweight. It records direction, priority, and status without deadlines or fixed milestones.

Priorities and statuses are planning aids, not commitments. They may change as the project develops.

## Priority levels

- **P0 — Foundation:** important for consistency or future work.
- **P1 — Core experience:** important to the intended Kawa experience.
- **P2 — Nice to have:** useful improvements that can wait.
- **P3 — Future / experimental:** ideas to revisit when the foundation is ready.

## Statuses

- **Planned:** accepted as a direction, but work has not started.
- **In Progress:** currently being worked on.
- **Completed:** implemented and verified.
- **On Hold:** intentionally paused.

An idea is not automatically planned just because it appears in a discussion. The project owner decides what enters or leaves this roadmap.

## Planned direction

### P0 — CLI consistency and standards

**Status:** Planned

- Define consistent command naming, aliases, arguments, options, and help conventions.
- Establish output and error-message standards.
- Review consistency across the existing commands.
- Keep Cute, Plain, and JSON modes predictable.

### P1 — Character foundation

**Status:** Planned

- Establish consistent character presentation.
- Define how Kawa reacts to commands and ordinary interactions.
- Keep personality and dialogue recognizable without making output noisy.

### P1 — Interaction and relationship

**Status:** Planned

- Add meaningful interaction with Kawa.
- Explore relationship / bond and mood systems.
- Let Kawa remember relevant interactions.
- Explore simple activities with Kawa.

### P2 — Personalization and terminal integration

**Status:** Planned

- Keep user preferences and interaction state locally.
- Explore a day-streak feature.
- Explore optional shell prompt integration.
- Consider presentation options that do not undermine the default personality.

### P3 — Future exploration

**Status:** Planned

- Explore richer terminal presentation.
- Explore additional interactions.
- Consider interfaces beyond the CLI, such as a TUI.

## Completed features

The following features are recorded as already implemented in the project:

- Minecraft coordinate conversion.
- Minecraft experience calculations.
- Minecraft item, stack, and shulker-box conversion.
- Uwuify.
- Coinflip.
- UUID generation.
- JSON pretty-printing.
- Cute, Plain, and JSON output modes.
- Command aliases and shell completion.

The code and tests remain the source of truth for exact behavior.

## Notes

- No deadlines or milestones are implied by priority.
- Priorities can change; this roadmap is not a promise to implement every idea.
- Completed means implemented and verified, not merely discussed.
- Major changes in product direction require approval from the project owner.
